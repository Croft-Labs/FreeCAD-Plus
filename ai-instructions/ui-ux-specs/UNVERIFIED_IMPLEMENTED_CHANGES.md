## E. Coverage boundaries and review priority

This register covers the complete archived numbered custom-screen inventory, component/document choices, interface integration and all transferred unconfirmed DOCX paragraphs. It does not claim every changed source line is a new design decision or that every feature works in the owner build. Algorithms, inherited bug fixes and unchanged native FreeCAD interfaces are not automatically unapproved UI changes. The [issue register](../archive/pre-restart-docs/FREECAD_ISSUES.md) retains inherited/fix status; the [roadmap](../archive/pre-restart-docs/DEVELOPMENT_ROADMAP.md) retains implementation and validation evidence.

Explicitly planned/uninstalled unified-feature and guided-workflow sections remain archived proposals, not implemented entries. Expanded Sketch Freedom/Constraint Repair, Interactive Feature Handles, Broken Reference Repair and revised Add Component remain deferred where the owner messages say so. Earlier bounded tools in this inventory do not authorize resuming those expansions.

Review in this order:

1. Ownership, references, suppression, output/BOM and recovery, which affect saved models and downstream behavior.
2. Overlapping workflows: Move or copy versus Move Components; old filters versus Design Selection; native Body/root restrictions versus component geometry; Add Reference Object versus mandatory Add Reference Feature.
3. Tree/task/ribbon state preservation, then exact controls and defaults.
4. Additional standalone dialogs and specialized manufacturing/drawing/review tools.

For each decision, cite the row ID, owner message/date, accepted behavior and destination specification. Keep undecided entries here. Never overwrite a confirmed requirement with an unreviewed entry, archive wording or implementation limitation.
