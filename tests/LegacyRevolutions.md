# Legacy revolution conversion

Task seven extends `LegacyConversion` and the shared component Revolve service.
Run `TestLegacyRevolutions` inside this fork's initialized native GUI with current
Part source modules and exact source `freecad.gui.ComponentNavigator`,
`ComponentExtrudeTask` and `ComponentRevolveTask` overlays. Initialize startup before
overlays and update GUI package attributes. Record actual paths/hashes, native exit
and suite counts. All fixtures/profiles/logs/renders belong in the owner-designated
validation directory and are removed after durable evidence is recorded.

## Native mapping and targets

Identity-frame Bodies containing independent native sketches and sequential
Revolution/Groove, optionally combined with qualified Pad/Pocket, use the existing
chain publisher extracted into `map_native_chain`. Preserve original names, types,
native IDs, UUIDs, labels, geometry, formulas and direct references. Intermediate
published results become explicit BaseFeature/ConsumedResults targets; the original
final Body stays the Result through the native child-scoped output bridge. Original
Origins remain. Every operation and final Body passes native volume and bidirectional
solid differences before the conversion transaction commits. Original FCStd bytes
remain protected; save converted documents to new cadprt files.

Qualification verifies Group/Tip, previous BaseFeature/Operation, sketch ownership,
independent attachments/formulas, native validity and one solid. Revolved features
retain native sketch horizontal/vertical/construction axes, ProjectAxis, Refine,
Reversed, one/two/symmetric angles, signed start offsets and Groove ThroughAll.
Linked start/end definitions and Body/datum/external axis frames stay native.
Other feature families remain outside this task. Pre-edit cache readiness prevents
promoting stale/invalid source output even if structural edits trigger recompute.
Task eight extends this same publisher/access-link contract to qualified mixed Loft
chains; see [LegacyLofts](LegacyLofts.md). Other families remain retained.

Shared Revolve reads these original parameters and edits supported angles, axes,
direction and compatible explicit targets in place. Formula overwrites and
self/downstream targets fail before mutation. A converted Revolution/Groove cannot
switch additive/subtractive native type: their C++ engines differ, and replacing
the object would violate legacy identity preservation. Create a separate Revolve
for that change. Same-type New Body/Add remains available. New Plus operations
retain their existing additive/subtractive replacement behavior and result UUIDs.

Whole-sketch scratch previews copy evaluated internal geometry and construction
flags into a temporary native sketch, retaining Placement without constraints or
cross-document links. This preserves the rotated angular start and native
construction-axis resolution, including the native `Axis` spelling for axis zero.
Selected-curve profiles retain the existing shape-helper preview path.

## Native retention and older files

Nonidentity/expressed Body frames, native attached sketches, datum/origin/external
axes, reference extents/starts, signed angular spans outside the shared contract,
unverified output and other mixed families retain native ownership, parameters and
available output. Hidden distinct-UUID Operation access links use
Body.Placement * Feature.Placement, LinkTransform false and LegacyRevolveSource.
LegacyRevolveTarget is a conversion-time BaseFeature snapshot; the original native
feature remains authoritative after edits. History opens the original editor;
missing/mismatched/invalid sources show Needs repair. These are retained parametric
engines, not physically promoted component operations or geometry-only replacements.

Standalone Part::Revolution has a distinct Source/vector-or-linked-axis/signed-angle/
Symmetric/FaceMaker contract. Preserve all original values and its native editor.
Verified single-solid output gains a published result; native sheet/curve/invalid
outputs stay retained and reported. Do not translate vector axis or negative Angle
to the PartDesign task. Explicit evaluated dumb body/sheet/curve/point recovery
remains the shared last resort when structural conversion fails; unavailable/stale
geometry is reported rather than invented.

LegacyRevolveVersion=1 is idempotent. Recognized prior converted files upgrade in
the existing transaction after manifest/identity verification; ordinary component
files are excluded. Promoted original input UUIDs and earlier sketch/extrusion access
link identities survive. Older access links become hidden Internal references
following their moved sources; History presents originals and explicit results.

## Acceptance and integration limits

Focused coverage includes exact shared-instance geometry and original identities,
conversion/edit Undo/Redo, rotated sketches, construction/horizontal axes, all side
modes and signed start-offset boundaries, reverse, formulas/refusal, ThroughAll,
explicit retargeting/type/cycle guards, original bytes, cold cadprt reopen/further
edits, retained attachment/reference frames and target snapshots, missing-source
repair, prior-file upgrades, signed standalone solid/sheet output and Pad/Revolution
chains. Actual Qt History double-clicks exercise shared Groove Preview/Accept/Cancel
after Undo/Redo and the original retained Groove editor. Regression suites cover
extrusion publishing, existing shared Revolve and prior migration/edit services.

WORK_STATE owns actual final counts/hashes, DOCX rendering, cleanup and publication.
Source-mode evidence does not qualify the installed owner payload. Packaging stays
batched. Arbitrary reference-frame promotion, external/cross-workbench mixed-history
acceptance and physical owner feedback remain integration gates. Task eight requires
its separate owner prompt.
