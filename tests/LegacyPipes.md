# Legacy Pipe migration acceptance

Task nine extends the shared native chain publisher and retained-operation access
links; it does not rebuild native geometry in a second sweep implementation.
`TestLegacyPipes.py` runs against this fork's native GUI with exact source overlays.
Installed delivery remains batched with migration integration.

## Mapping contract

Independent native AdditivePipe/SubtractivePipe chains, including qualified prior
Pad/Pocket/Revolution/Groove/Loft features, retain original names, types, native IDs,
UUIDs and labels. Profile and ordered Sections, Spine and AuxiliarySpine retain
their original objects and subelement strings. Every profile/path/auxiliary sketch
appears once before its consuming operation in component History. Shared definition
instances retain their placement and LinkTransform semantics.

The original final Body remains the result through the existing child-scoped Tip
bridge. Intermediate published results provide explicit BaseFeature/ConsumedResults
targets. Native evaluation and volume/bidirectional differences qualify every
mapped operation and final Body before the transaction commits.

Standard/Fixed/Frenet/Auxiliary/Binormal, native corner transitions,
Constant/Multisection, Binormal, tangent flags, AuxiliaryCurvilinear, Refine and
FuzzyTolerance remain authored native settings. Only independent sketch inputs,
whole closed profiles, connected sketch paths and qualified Boolean targets map.
Blank whole-profile subreferences are retained. Selected path edges remain exact.
Body placements/expressions, attached/dependent/non-sketch inputs, profile edge
references with native whole-sketch semantics, point sections, inactive extra
sections, unsupported scaling modes, Common/no-material histories and invalid or
unverified output keep the original native ownership and editor. This bounded
qualification must not rewrite a native reference as a different shared input.

Converted shared Pipe edits preserve original native types/identities across
Add/Subtract/New Body through persisted native Boolean presets, including Common
when explicitly requested for a shared edit. Formulas remain in properties rather
than being overwritten by the task. New Body clears target consumption. Invalid
paths, cyclic targets and ineffective edits fail without changing saved settings.
Unavailable selected edges become a normal repair message, not an uncaught index
exception. Nullable native auxiliary references are read as no auxiliary path.

Retained History links have distinct UUIDs and complete Body/feature placement
expressions. LegacyPipeTarget records the conversion-time target; original native
parameters remain authoritative. Missing/mismatched/invalid source links report
Needs repair. Standalone Part Sweep retains Sections, Spine, Solid, Frenet,
Transition and Linearize on its original native engine/editor; verified solids
gain a published result, while sheets/invalid/unverified output stay retained.

LegacyPipeVersion=1 upgrades recognized prior converted files after manifest
validation. Earlier sketch/operation access identities and labels survive promotion
as hidden Internal references. Ordinary new Plus documents do not migrate. Original
FCStd bytes stay protected. The shared structural recovery path still prefers
native editability, then explicitly labelled evaluated dumb body/sheet/curve/point;
stale or unavailable geometry must be reported, never silently treated as converted.

## Verification

The focused tests cover native/shared History double-clicks, Preview/Accept/Cancel,
conversion/edit Undo/Redo, save/cold reopen and further path edits, all orientations
and corner transitions, Multisection order, exact path picks, geometry and shared
instance frames, mixed Pad/Pipe targets, both original native types, Common preset
cold restore, formula preservation/refusal, missing edges, failed geometry rollback,
attached/whole-sketch/native Common/stale retention, standalone solid/sheet controls,
older-file UUID-preserving upgrades and idempotence.

Run shared Pipe/Loft and prior migration/recovery suites for the common chain/editor
changes. WORK_STATE owns actual counts, loaded source hashes, diagnostics, document
render/inspection, cleanup and publication. Source-mode success does not qualify
the installed owner's payload or establish warning-free native editing.
