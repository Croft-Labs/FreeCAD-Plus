## Sections, original identities and targets

Qualified identity-frame Bodies with independent native sketches and sequential
Loft operations, optionally mixed with previously qualified Pad/Pocket/Revolution/
Groove, reuse `map_native_chain`. `native_sections` preserves original Profile and
Sections order and subelement spelling. Every native section input precedes its
operation in component History; shared sources move once. Original names, native
types/IDs, UUIDs, labels, constraints, formulas and direct references remain.
Intermediate published results become explicit BaseFeature/ConsumedResults targets.
The original final Body remains the Result with its Origin/view provider and hidden
native Tip bridge. Every feature and final Body must pass volume and bidirectional
solid differences inside the conversion transaction.

Admission verifies exact Group/Tip, native BaseFeature order, Boolean operation,
all section owners/dependencies/states, valid one-solid output and pre-edit cache
readiness. Loft admits whole independent sketches and native vertex picks at open
end sections. It preserves Smooth/Ruled, Closed, Refine and bounded native fuzzy
tolerance. Closed requires at least three distinct sections; repeated identical
references, non-sketch inputs, attachments/Body-dependent frames, reference formulas,
unsupported tolerances and other families remain native. Native no-material Loft
histories also remain native because the shared editor rejects no-op Add/Subtract.

Legacy native Loft treats Part2D edge subreferences as the **entire sketch**, except
vertex picks. Shared selected-curve sections instead create subset helpers. Preserve
these legacy references and native engines rather than silently changing the
selection contract. Current physical promotion is bounded; native retention is
editable access with available output, not a claim of universal component mapping.

## Shared editing and Boolean identity

Shared Loft loads saved ordered sections/options/targets and supports section
reorder, replacement, preview, parameter edits and retargeting. Self/downstream
references, formula overwrites and ineffective/invalid edits fail without mutation.
Converted Lofts change New Body/Add/Subtract using the same native feature/type/ID.
The native Loft kernel uses FeatureAddSub's Boolean maker; its constructors restrict
the preset enumeration. On a converted edit only, persist a custom Union/Subtraction/
Common enumeration before setting the requested Union/Subtraction value. Native
PropertyEnumeration serialization restores that enumeration and Boolean mode.
No C++ engine replacement, renamed feature or redirected original consumer is needed.
New Plus Lofts retain their existing native-type replacement/result-UUID behavior.
Common authored before conversion remains native and is not relabeled Add/Subtract.

New Body clears consumption; other modes record the explicit target and restore
visibility on Cancel/rollback/Undo. Original section sketches remain associative:
later constraint/placement edits recompute original features, results and shared
instances. Native section geometry, previews and downstream results remain tested
separately; a dialog alone is not acceptance.

## Retained engines, standalone Loft and upgrades

`retain_native_operation` now serves Extrude/Revolve/Loft through the same hidden
distinct-UUID Operation access-link contract. Preserve native ownership and set
LinkTransform false with Body.Placement * Feature.Placement. LegacyLoftSource opens
the original editor; LegacyLoftTarget records the conversion-time BaseFeature.
The original native target remains authoritative after native edits. Links are not
assembly instances or physical results. Missing/mismatched/invalid sources show
Needs repair. Original support references, section order and formulas remain intact.

Standalone Part::Loft has separate Sections LinkList, Solid, MaxDegree, Linearize,
Ruled and Closed semantics. Keep its native object/settings/editor; verified solids
gain a published result while native sheet/curve/invalid output remains retained and
reported. Do not reinterpret these as PartDesign Loft parameters. Original FCStd
bytes remain protected; save new cadprt files. Existing explicit evaluated dumb
body/sheet/curve/point recovery remains the last structural fallback, retaining
native payloads and reporting stale or unavailable geometry rather than inventing it.

LegacyLoftVersion=1 upgrades recognized prior converted files after manifest/identity
validation in the existing transaction. Preserve section sketch UUIDs and older
access-link identities; promoted links become hidden Internal references following
their moved sources. Conversion is idempotent. Ordinary new component files are
outside the legacy upgrade.
